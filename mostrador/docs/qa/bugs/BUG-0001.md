# BUG-0001: Otro negocio podía resolver lotes, cancelar ventas o dar entradas ajenas
- **Funcionalidad:** base de datos (funciones `mos_resolver_lote`, `mos_cancelar_venta`, `mos_entrada`)   **Giro(s):** todos   **Rol:** usuario de otro negocio
- **Prioridad:** Crítica   **Estado:** Verificado

## 1. Descripción del problema
La revisión de permisos `mos_rol(negocio) not in ('dueno','encargado')` daba NULL (no falso) cuando el usuario no pertenece al negocio, y la condición no detenía la operación.
## 2. Pasos para reproducirlo
1. Usuario A crea negocio y un lote con caducidad.
2. Usuario B (de otro negocio) llama `mos_resolver_lote(<lote de A>, 'merma')`.
## 3. Resultado esperado
Error "Sin permiso".
## 4. Resultado obtenido
La merma se registraba en el inventario de A.
## 5. Nivel de prioridad
Crítica: un negocio podía alterar datos de otro.
## 6. Posible solución (aplicada)
`coalesce(mos_rol(...), '') not in (...)` en las 3 funciones. Migración `mostrador_fix_permisos_null`. Regresión: 5/5 casos de aislamiento pasan.
